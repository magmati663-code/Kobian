# Notatki — US-29 eksport/import zadań JSON bez sekretów (W=/tmp/kb/w-export)

ID planu: US-29 (AC-29.1, AC-29.2), SEC-6.7, STRIDE „Import zadań (US-29) — wykonanie kodu jako usługa” (AS-02), 6.8 (CLI), BL-47, SEC-3.3 (limity), kontrakt D2.10 (`ExportJobs`/`ImportJobs` = Admin).

## Co zrobiono
1. **Format `kobian-export v1`** — `JobExportFormat` (czysta logika): dokument `{format, version, programVersion, exportedAt, jobs[{name,type,enabled,timeZone,misfire,misfireWithinSeconds?,schedule?{cron,enabled},definition}]}`; definicja v1 tylko z pól schematu (secretRef = nazwa, pliki klucza/hasła/nagłówka/certyfikatu = ścieżki). Postać kanoniczna: klucze sortowane ordinal na każdym poziomie, zadania po nazwie, bez `null`, wcięcie 2, LF, ASCII (`\uXXXX`). Odczyt ścisły: rozmiar ≤ 60 KiB, głębokość ≤ 8 (liczona na bajtach przed parsowaniem), ≤ 200 zadań, napis ≤ 1024, duplikaty kluczy (`AllowDuplicateProperties=false`) i nazw zadań, pola nieznane = odrzucenie (nie ignorowanie), pola akcji/skryptów = KB-0123, pola/wartości sekretopodobne = KB-0122, potem `JobDefinition.Parse` (te same reguły co przy uruchomieniu), harmonogram (cron ≥ 5 min w strefie zadania), strefa, misfire. Wynik: lista problemów (ścieżka JSON + KB + stały powód, bez wartości, ≤ 100) — cały plik albo nic (AC-29.2).
2. **Agent** — `JobTransferService`: eksport z job_jobs + sched_triggers (`cron-<job_id>`); zapisana definicja niezgodna ze schematem/z sekretem → odmowa eksportu (nie „wycinanie”). Import: walidacja formatu → reguły kreatora (`JobDraftValidator`: źródło czytelne KB-0101, cel KB-0103/21xx, nakładanie KB-0102; dla „database” `ValidateShape`) → materiał klucza tylko ze ścieżek lokalnych → plan (new/unchanged/conflict; skip/overwrite/rename/blocked, flagi `needsCredentials` (brak `<secrets>/<nazwa>.json`) i `missingKeyMaterial`) → zapis w JEDNEJ transakcji `CatalogWriter.ExecuteControlAsync` z ponownym planem w transakcji (TOCTOU). Zadania nowe/nadpisane `enabled=0`, nadpisanie zachowuje job_id (historia), zadania `protected` nie nadpisuje (KB-0124). Nic nie uruchamia (test: brak run_runs).
   RPC na końcu serwisu `Agent` w `agent.proto`: `ExportJobs(ExportJobsArgs{jobs[]})`, `ImportJobs(ImportJobsArgs{document, validate_only, on_conflict})`, enum `ImportConflictMode`, `ImportIssue`, `ImportChange` (wiadomości dopisane na końcu pliku). `MethodPolicy`: oba **Administrator** (plan D2.10 tak mówi — zadanie sugerowało Reader/Operator „wg planu”; plan = Admin); `ExportJobs` niemodyfikujące, ale **audytowane** — nowa flaga `MethodPolicy.Entry.Audited` + 1 warunek w `AgentCallInterceptor`. `AgentCallAudit.Describe`: import → `sha256`, `bytes`, `validate_only`, `on_conflict` (bez treści); eksport → target = nazwy lub `*`. `IAgentBackend` metody domyślne (KB-7012), `CatalogAgentBackend.JobTransfer { init; }`, Program.cs (wydzielony `jobValidator`, `SecretsDirectory = secretsDir`). `ApiConventions.MaxJobsDocumentBytes = 60 KiB` (wspólne dla Agenta i CLI).
3. **CLI** — `kobian export [--job <n>]... [--output <plik> [--force]] [--json]` (bez `--output` dokument na stdout; plik CreateNew, 0600 na Unix; JSON `kobian.cli.export/1` z jobs/output/sha256), `kobian import <plik> [--dry-run] [--on-conflict skip|overwrite|rename] [--json]` (JSON `kobian.cli.import/1`: result, code, dryRun, applied, changes[], issues[]). Kody: 0/2/3/64; plik > 60 KiB → KB-0121 (kod 2) bez wywołania Agenta; zła wartość `--on-conflict` → 64. `Args.Options()` (powtarzalne `--job`), `IsValued` + `--output`, `--on-conflict`.
4. **Docs**: `docs/admin/eksport-import-zadan.md` + `.en.md` (format, limity, konflikty, kody), sekcja w `docs/agent-api.md`, wskazanie w `docs/agent-job-definition.md`, wiersz w `docs/README.md`, `docs/kb-codes.md`/resx (generowane), `docs/ac-coverage.md` (regenerowane `tools/ac-coverage.py` — AC-29.1/29.2 „tak”).

## Przegląd bezpieczeństwa
Lista kontrolna: brak sekretów w kodzie/testach (losowe w teście), brak sekretów i wartości pól w komunikatach/odpowiedziach/audycie (nazwy pól z pliku w ścieżkach błędów sanityzowane do `[A-Za-z0-9_-]`, ≤ 64), brak Process.Start/skryptów, SQL tylko z parametrami, SHA-256 (nie MD5/SHA-1), `RandomNumberGenerator` dla job_id, limity wejścia (rozmiar przed parsowaniem, głębokość bez rekursji, liczba zadań/problemów, długość napisów), parser bez „ostatni wygrywa”, brak kontaktu sieciowego przy imporcie z plików klucza UNC.
STRIDE nowych elementów:
- S: wywołujący z roli z tokenu pipe (istniejące); oba RPC wymagają Administratora.
- T: plik importu modyfikowany przez atakującego → ścisły schemat, reguły kreatora, wyłączone zadania, atomowość, audyt skrótu SHA-256 pliku.
- R: audyt eksportu (nowe `Audited`) i każdego importu, także dry-run i odmów.
- I: eksport ujawnia ścieżki/hosty/nazwy sekretów (nie wartości) → tylko Admin, audyt; eksport odmawia, gdy w katalogu jest definicja spoza schematu (nie przeniesie przemyconego pola).
- D: limity 60 KiB/8/200/1024/100 problemów; walidacja źródła per zadanie (≤ 200 enumeracji katalogu).
- E: brak akcji/skryptów (KB-0123), zadania wyłączone, brak uruchomienia; nadpisanie chronionego zablokowane.
Znaleziska: Wysokie — brak. Średnie — brak. Niskie: (1) CLI mapuje PermissionDenied na kod 3 „brak usługi” (istniejące zachowanie GrpcAgentClient — dla eksportu/importu Reader/Operator dostaje 3, nie komunikat o roli); (2) heurystyka sekretów może dać fałszywy alarm (np. losowa nazwa zadania ≥ 20 znaków) — skutkiem jest bezpieczne odrzucenie; (3) walidacja źródła UNC w dry-run łączy się z serwerem SMB na koncie usługi — tak samo jak istniejący `UpsertJob validate_only` (rola Admin); (4) nadpisanie definicji zadania w trakcie jego uruchomienia nie czeka na koniec (uruchomienie kończy się na starej definicji, zadanie zostaje wyłączone).

## Decyzje PROWIZORYCZNE (do nadania Qb)
- **Qb-NEW-import-size** (`ApiConventions`, `JobExportFormat`): limit dokumentu 60 KiB (jedna wiadomość gRPC, host przyjmuje ≤ 64 KiB), eksport większy = KB-0121 (eksport częściami `--job`). Alternatywa: strumień klienta w kawałkach z limitem 1 MiB. Koszt: mały.
- **Qb-NEW-import-secret-heuristics**: wartość sekretopodobna = odrzucenie (PEM, `password=`, URL z hasłem, JWT, hex ≥ 32, token ≥ 20 o entropii ≥ 4,2 z cyframi i literami; w polach ścieżek tylko wzorce jednoznaczne). Alternatywa: ostrzeżenie. Koszt: mały.
- **Qb-NEW-import-key-paths**: `key.file/passwordFile/repoHeader` w imporcie tylko lokalne (UNC/urządzenie = KB-0103), by sprawdzenie istnienia nie łączyło usługi z obcym SMB. Alternatywa: zezwolić bez sprawdzania. Koszt: mały.
- **Qb-NEW-import-actions**: AC-29.1 mówi „akcje nieaktywne do zatwierdzenia przez Admin”; definicja v1 nie ma modelu akcji, więc plik z akcjami/skryptami jest odrzucany w całości (KB-0123), `quarantined_actions` = 0. Po wprowadzeniu akcji: import z kwarantanną. Koszt: średni.
- **Qb-NEW-import-disabled**: zadania nowe/nadpisane zawsze wyłączone (pole `enabled` z pliku informacyjne). Alternatywa: zachować stan. Koszt: mały.
- **Qb-NEW-import-source-check**: źródło musi być czytelne na serwerze docelowym już przy imporcie (reguła kreatora) — inaczej cały plik odrzucony. Alternatywa: ostrzeżenie w planie. Koszt: mały.
- Rola eksportu = Administrator (zgodnie z kontraktem D2.10 w planie; zadanie sugerowało Reader/Operator). Odwracalne w `MethodPolicy` (1 linia). Uwaga: SCR-04 w planie wymienia `ExportJobs` przy roli Viewer (odczyt) — sprzeczność w planie do rozstrzygnięcia przez PO.
