# ADR-0031 — Podgląd odtworzenia PlanRestore (R2.8.1, SCR-07) — PROWIZORYCZNIE Qb48

- Data: 2026-10-17, iteracja 98 (prowadzi rola 8; 6, 2, 11). Status: przyjęte prowizorycznie (Qb48).
- Kontekst: R2.6.1 SCR-07 = „plan + start”, R2.8.1 PlanRestore (dry-run: liczby, konflikty, bez zapisu), AC-07.2 (odmowa przed odczytem danych). Do it. 97 UI odtwarzało od razu; konflikty były widoczne dopiero w wyniku (KB-5105).
- Decyzja: `RestorePlanner` (Engine/Restore) przechodzi drzewa z TYM SAMYM wyborem co `RestoreExecutor` (wydzielone `ExactPathSelection`, `RestoreTarget`) i liczy: pliki/bajty, nowe foldery, konflikty (+ ≤ 20 przykładów), niedozwolone nazwy, dowiązania, brakujące bloki, packi i bajty ramek do odczytu (z indeksów), wolne miejsce. Blokady: KB-5003, KB-5202, KB-5001 (plik próbny CreateNew + DeleteOnClose), KB-5106 (nowy kod: wolne < bajty bez konfliktów, bez zapasu). RPC `PlanRestore(RestoreRequest) → RestorePlanReply` (Operator, niemodyfikujące, bez wiersza run_runs). UI: „Odtwórz” = najpierw plan; czysto → od razu odtworzenie; pominięcia → przycisk „Odtwórz mimo to”; blokada → komunikat KB i start wyłączony do zmiany folderu. CLI `restore --dry-run`.
- PROWIZORYCZNIE: (a) prawo zapisu sprawdzane na koncie procesu Agenta (w usłudze: NT SERVICE\KobianAgent), nie tokenem klienta — SEC-6.3 wymaga AccessCheck z tokenem klienta (W-40, port do zrobienia z BL-75); (b) wolne miejsce bez zapasu na metadane NTFS; (c) przykładowe ścieżki konfliktów wracają do UI (to nazwy z kopii, którą wywołujący i tak przegląda w SCR-06).
- Konsekwencje: dodatkowe przejście drzew przed odtworzeniem (koszt ≈ czas BrowseTree całej kopii; pamięć 32 B/unikalny blok); stary Agent (Unimplemented) → UI odtwarza bez podglądu.
- Alternatywy: plan jako osobny przycisk „Sprawdź” (więcej kliknięć); blokada przy każdym konflikcie (sprzeczne z D8.9 „pomiń i wykaż”); zapas 5% miejsca.
- Koszt zmiany zdania: mały (parametry `FreeBytes`/`CanWrite` planera, logika `StartAsync`).
