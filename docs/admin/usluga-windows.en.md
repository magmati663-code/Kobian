# Kobian Agent as a Windows service (BL-72, it. 91)

> Status: service host code is done and tested on Linux (paths, single instance, ACL plan); behaviour under SCM, Event Log and pipe ACL **requires Windows** (queue W-33/W-34). Production install = MSI (later); below is a developer install.

## Service profile (D2.5, D2.12 — `AgentServiceProfile`)

| Setting | Value |
|---|---|
| Name / display name | `KobianAgent` / "Kobian Backup Agent" |
| Account | virtual `NT SERVICE\KobianAgent` (not Administrators/Backup Operators, not LocalSystem) |
| Start | Automatic (Delayed Start) |
| Token privileges | `SeBackupPrivilege`, `SeRestorePrivilege`, `SeChangeNotifyPrivilege`, `SeShutdownPrivilege` (no `SeImpersonatePrivilege`) |
| Recovery | restart after 1 min, 1 min, then every 5 min; failure count reset after 1 day (NFR-09) |
| Service SID | Unrestricted (SP-13 to be confirmed) |
| VSS | `HKLM\SYSTEM\CurrentControlSet\Services\VSS\VssAccessControl` → `NT SERVICE\KobianAgent` = 2 |

## Paths (PROVISIONAL Qb41)

| Mode | `catalog.db` | State | Secrets |
|---|---|---|---|
| Service (SCM) | `KOBIAN_CATALOG` or default `%ProgramData%\Kobian\catalog.db` | `KOBIAN_STATE_DIR` or the catalog's folder | `KOBIAN_SECRETS_DIR` or `<state>\secrets` |
| Console (dev) | `KOBIAN_CATALOG` required (relative = current directory) | as above | as above |

In service mode every path must be absolute. Always rejected: UNC and device paths (`\\server\…`, `\\?\…`) and control characters. Configuration error = exit code **64** (Event Log entry when the `KobianAgent` source is registered).

## Single instance (D2.15 item 3, AC-37.3)

Before opening the catalog the Agent takes `catalog.db.lock` exclusively (contains the PID, never deleted) and — on Windows — the mutex `Global\Kobian.Agent.Instance`. A second instance exits with code **75** and **KB-7007** without changing `catalog.db`.

## API pipe in service mode (D2.9, D2.15 item 1 — `AgentPipeAcl`)

`CurrentUserOnly = false` with an explicit ACL: **Deny** `NT AUTHORITY\NETWORK`; service account — read/write + create instance; `SYSTEM`, `Administrators`, `Kobian Operators` and `Kobian Admins` (if the groups exist; `Kobian Admins` — PROVISIONAL Qb45) — read/write only. Other users — no access. Console mode keeps `CurrentUserOnly = true` (fixed Operator role).

### Caller roles (BL-17, D2.9)

The service reads the client's SID and groups from the connection token (`RunAsClient`, Identification level — the client does not let the service act on its behalf). The result is cached for the connection.

| Client token | Role |
|---|---|
| `SYSTEM`, Administrators **elevated (UAC)**, `Kobian Admins` | Administrator |
| `Kobian Operators` (also a non-elevated administrator who is a member) | Operator |
| any other ACL-admitted caller | Reader |
| anonymous token, network logon (`NETWORK`), no token or read error | denied `KB-7001` |

A non-elevated administrator holds Administrators as deny-only — run the console "as administrator" for changes that need the Administrator role. The audit log records the caller's SID (`actor_sid` column). Windows verification: W-17, W-37.

## Developer install

Use the `sc.exe` commands listed in the Polish version (`usluga-windows.md`), generated by `AgentServiceProfile.ScCommands(...)`, plus `New-EventLog -LogName Application -Source KobianAgent`.

## MSI installation and system configuration (it. 100–103 — skeleton, PROVISIONAL Qb50/Qb53)

The MSI (`installer/Package.wxs`, built on Windows after decision Q37 — W-42) installs the service with the profile above (native MSI tables instead of `sc.exe`) and, once it exists, runs **`Kobian.Agent.exe --provision`** as LocalSystem. This mode does not start the service or touch the catalog; it runs, in order (the first failure aborts the installation; MSI log shows `ok <step>` / `failed <step> (win32 <code>)`):

| Step | What it does |
|---|---|
| `group-operators`, `group-admins` | creates local groups “Kobian Operators” and “Kobian Admins” (existing ones keep their members) |
| `data-dir`, `data-secrets`, `data-keys`, `data-certs`, `data-staging` | `%ProgramData%\Kobian` and subfolders: owner Administrators, **non-inherited** ACL — SYSTEM, Administrators, `NT SERVICE\KobianAgent` full control; Kobian groups and users — none (API only); a folder that is a link → refused |
| `vss-access` | `HKLM\SYSTEM\CurrentControlSet\Services\VSS\VssAccessControl\NT SERVICE\KobianAgent = 2` |
| `lsa-rights` | SeBackupPrivilege, SeRestorePrivilege and SeShutdownPrivilege for the service account |

Uninstall runs `--unprovision` (removes the VSS value and LSA rights; failures do not block uninstall). **Data (`%ProgramData%\Kobian`: catalog, keys, secrets) and groups are kept** — remove them manually if you really want to (backup repositories on destinations are not touched).

Restore target (since it. 101): an Operator may restore only into a folder where their own account may add files and folders (AccessCheck with the client token) — otherwise KB-5001; Administrators are not restricted.

Helper process `Kobian.Worker.exe --role vss` (D2.8) — VSS snapshot requester in a separate process; until spike SP-01 is done it returns KB-1406 (snapshot unavailable). A start blocked by WDAC/AppLocker/ASR will be reported as KB-7008.
